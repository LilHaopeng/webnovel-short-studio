# 轻量产物契约、网感分布体检与纯净导出

在初始化项目、写后复核（`check`）或最终导出（`export`）时读取。

---

## 1. 极简项目目录（为高频“垒量”减负）

整篇 1–5 万字短篇只保留 **2 个极轻的工作文件**，不建厚重世界观树，不拆 L0–L5 六层大纲，不维护多余台账：

```text
{项目根}/
├── 00_脑洞与节拍.md         # 唯一上位锚点：一页高概念规则卡 + 爽感叠加节拍表 + 200–300字原声定调切片 + 上游选题备注
├── 01_轻量状态.md           # 10–20 行动态便签：当前进度、已埋/待收明牌线索、核心人物最新筹码、上一节末尾衔接
├── 正文/
│   ├── 第001章_章名.md      # 纯净正文（超短篇也可按节命名，如 01_开局.md 或单文件 01_全文.md）
│   └── ...
└── 交付/
    ├── {书名}_全文.docx     # 供编辑审阅与手机/屏幕阅读的纯净 DOCX
    └── {书名}_平台发布.txt   # 供番茄/知乎/投稿后台直接复制粘贴的纯净 TXT
```

### 纯净正文纪律
- `正文/*.md` 中**只允许出现章/节标题（`# 标题`）与小说正文**（场景硬切可用空行或居中 `* * *`）。
- 禁止把节拍编号、爽感维度标签、字数统计、`[待确认]` 或自检说明混进正文文件。

---

## 2. 轻量连续性回写（每章/每节写完花 10 秒）

每次写完一章或一个大节，用最短的条目更新 `01_轻量状态.md`，只记 4 件事：
1. **进度与累计字数**：已写到哪一节、累计约多少汉字。
2. **明牌线索清单**：哪些伏笔/规则细节已经亮在纸面上（状态：`已埋` / `已回收`），避免后面反转忘圆或提前漏底。
3. **关键人物当前筹码**：主角和核心对手此刻手里握着什么牌、刚失去什么、以为对方是什么底细。
4. **章末原文 1–2 句**：方便下一节秒接情绪和现场，不用重读全文。

## 3. 网感分布体检仪（`lint_webnovel.py`）使用与解读

初稿完成后运行：

```text
# 单章体检
python <skill-dir>/scripts/lint_webnovel.py --file <正文文件> --narrative <dialogue|first_person|rules>

# 首章额外检查黄金前 500 字入局
python <skill-dir>/scripts/lint_webnovel.py --file <首章文件> --narrative <dialogue|first_person|rules> --first-chapter

# 全篇一键汇总体检
python <skill-dir>/scripts/lint_webnovel.py --dir <正文目录> --narrative <dialogue|first_person|rules>
```

### 它查什么（只查“分布级跑偏”，绝不做单段 70 字硬红线）

| 体检信号代码 | 触发逻辑（随 `--narrative` 自适应） | 真正要排查的问题 |
|---|---|---|
| `heavy_paragraph_distribution` | 整章**中位段长 > 68 字**，或 `>95` 字重度长段占比偏高（`dialogue` >25%，`first_person`/`rules` >35%） | 整章不知不觉滑回了传统出版长段密度，手机阅读发沉 |
| `narration_wall_streak` | 连续多段纯旁白无对话且累计字数过重（`dialogue` ≥5 段且 ≥260 字；`first_person`/`rules` ≥7 段且 ≥400 字） | 局部出现连续几屏的“纯叙述闷段”，节奏掉速 |
| `low_dialogue_ratio` | **仅 `dialogue` 模式启用**：对白字数占比 < 28% | 强对话交锋型题材写成了旁白转述型 |
| `long_speech_monologue` | 单句未打断台词 > 110 字，或同段单回合合计发言 > 125 字 | 角色站桩发表百字政策/逻辑演说，建议拆成多轮交锋 |
| `choppy_telegraph_uniformity` | 连续 ≥12 段非对白短段全部挤在 12–38 字且方差极小 | **反向 AI 味预警**：机械切段写成了均匀“AI 电报排骨”，需恢复自然长短起伏 |
| `opening_exposition_wall` / `opening_low_energy` | **仅首章启用**：前 2 段即出现 >130 字长铺陈，或前 500 字既无对白也无强标点/动作爆发 | 黄金 500 字入局偏慢，容易在前两屏流失读者 |
| `mixed_quote_styles` | 同章同时混用全角双引号 `“”` 与直角引号 `「」` | 对话引号格式不统一；知乎盐言应统一用 `「」`，其他平台统一用 `“”` |
| `ai_*` / `cliche_*` | 匹配极简列表中的纯翻译腔或工业神态废料 | 自动驾驶漏出的套话，顺手换回当下具体表达 |

### 解读铁律（防应试写作）

1. **所有输出都是 `ADVISORY`（诊断参考），不是必须清零的报错**。
2. 如果某章确实因为规则清单、高密度毒舌独白或悬疑铺压触发了 `heavy_paragraph_distribution` 或 `narration_wall_streak`，而通读下来**手机滑读体感很爽、气口很足**，直接保留，绝不为了消提示去硬敲回车或硬塞废话对白。
3. 真正需要动刀的是两种情况：
   - 肉眼一看确实不知不觉写成了密密麻麻的出版腔/评审会演讲腔；
   - 或者反过来触发了 `choppy_telegraph_uniformity`，满屏清一色两行一段像提词器。

## 4. 纯净导出（DOCX + 平台发布 TXT）

完稿或阶段交稿给编辑/平台时运行：

```text
python <skill-dir>/scripts/export_short.py \
  --chapters-dir <正文目录> \
  --out-docx <交付目录>/<书名>_全文.docx \
  --out-txt <交付目录>/<书名>_平台发布.txt \
  --title <书名> \
  --preset screen
```

- `--out-docx`：生成适合编辑与屏幕审阅的纯净 `.docx`（默认 `screen` 轻读预设，无首行缩进、清爽段距、自带封面与总字数统计；如需传统书页首行缩进可切 `--preset book`）。
- `--out-txt`：生成去掉所有 Markdown 语法与多余空行的纯净 `.txt`，可直接粘贴至番茄/知乎/七猫等平台编辑器。
- 内置工程标记拦截：若正文残留 `[待确认]`、`{{...}}` 或内部编号，导出会报错提醒清理，防止半成品误发。
