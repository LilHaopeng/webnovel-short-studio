# 轻量产物契约、番茄投稿前分布体检与纯净导出

在初始化项目、写后复核（`check`）或最终导出（`export`）阶段读取。

---

## 1. 极简项目目录（仅 2 份核心工作文件）

```text
{项目根}/
├── 00_脑洞与节拍.md         # 唯一上位锚点：一页规则与关系卡 + 爽感节拍表 + 200–300字原声切片 + 上游备注
├── 01_轻量状态.md           # 10–20 行动态便签：进度、明牌线索、核心人物最新筹码、上节末尾衔接
├── 正文/
│   ├── 第001章_章名.md      # 纯净正文（单换行即分段；超短篇也可按节或单文件命名）
│   └── ...
└── 交付/
    ├── {书名}_全文.docx     # 编辑审阅与屏幕轻读版 DOCX
    ├── {书名}_平台发布.txt  # 平台后台直接粘贴的纯净 TXT
    └── {书名}_投稿建书清单.md # 按需配套产出（面向七猫/番茄）
```

**纯净正文纪律**：`正文/*.md` 只允许章/节标题（`# 标题`）、小节标、场景分割线（`* * *`）与小说正文，严禁混入内部 ID、节拍号、字数统计、`[待填]` 或审校注释。

---

## 2. 轻量连续性回写（每章写完花 10 秒）

更新 `01_轻量状态.md`，只记 4 项：① 进度与累计净汉字；② 明牌线索与感官物象（`已埋`/`已回收`）；③ 核心人物当前筹码、情绪温度与对手盲区进度；④ 章末 1–2 句原文以便无缝续写。

## 3. 网感分布与番茄投稿前体检仪（`lint_webnovel.py`）

```text
# 单章常规体检（默认不开启平台字数硬限）
python <skill-dir>/scripts/lint_webnovel.py --file <正文文件> --narrative <dialogue|first_person|rules>

# 首章检查（文件名含 第1章/第一章/第001章/01_/序章 自动触发，也可显式加 --first-chapter）
python <skill-dir>/scripts/lint_webnovel.py --file <首章文件> --narrative <dialogue|first_person|rules> --first-chapter

# 整本批量体检 + 番茄投稿前专项 + 人物名拼写漂移核验
python <skill-dir>/scripts/lint_webnovel.py --dir <正文目录> --narrative <dialogue|first_person|rules> --platform fanqie --char-card <项目根>/00_脑洞与节拍.md

# 知乎盐言直角引号核验 / 七猫上传硬限按需排查
python <skill-dir>/scripts/lint_webnovel.py --dir <正文目录> --platform zhihu
python <skill-dir>/scripts/lint_webnovel.py --dir <正文目录> --platform qimao --check-title "<书名>"
```

> **平台上传硬限默认关闭**：`--platform` 默认 `none`，不套用侧边单章字数限制干扰写作流畅度。仅当用户明确要求核查平台规格时传入：
> - `fanqie`：强调番茄 2026-11 投稿前排版/语病自查，**不设人为单章字数硬限**；
> - `zhihu`：核验对话是否统一采用直角引号 `「」`（嵌套 `『』`）；
> - `qimao`：按统一非空白字符数（`non_ws_chars`）核验单章 `500–1500` 字及书名 `≤18` 字。
> - `--dir` 批量模式下，首章黄金 500 字检查**仅对首章（`idx == 0`）生效**。

### 信号全表（全部为纯 `ADVISORY` 诊断参考，脚本恒返回退出码 `0`）

| 体检信号代码 | 触发逻辑与豁免 | 要排查的问题 |
|---|---|---|
| `heavy_paragraph_distribution` | 中位段长 >68 字，或 >95 字段占比超限（`dialogue` >25%，`first_person`/`rules` >35%） | 整章滑回出版长段密度，手机阅读发沉 |
| `narration_wall_streak` | 连续纯旁白无对白且字数偏重（`dialogue` ≥5 段且 ≥260 字；`first_person`/`rules` ≥7 段且 ≥400 字） | 局部出现连续纯叙述闷段 |
| `low_dialogue_ratio` | 仅 `dialogue` 模式：对白字数占比 <28% | 强对话题材写成了旁白转述 |
| `long_speech_monologue` | 单句未打断台词 >110 字或同段单回合发言 >125 字 | 角色站桩发表百字演讲，建议拆成多轮交锋 |
| `choppy_telegraph_uniformity` | 连续 ≥12 段非对白短段挤在 12–38 字且标准差 ≤5.5（`rules` 模式编号清单豁免） | 反向 AI 味“电报排骨体”，需恢复长短起伏 |
| `opening_exposition_wall` / `opening_low_energy` | 仅首章：前 2 段出现 >130 字纯旁白，或前 500 字平铺长说明（无对白、无紧凑短段且无冲突张力） | 首章黄金 500 字入局偏平缓（不强求感叹号） |
| `bare_dialogue_stack` | 连续 ≥5 句无动作/神态穿插的纯短对白（≤28 字）；**短信/微信/电话/弹幕/论坛/群议豁免** | 番茄「短对话堆砌」红线，面对面交锋最多连 2–3 句裸接 |
| `staircase_micro_paras` | 连续 ≥4 段 1–10 字非对白、非系统面板/规则条目碎段 | 番茄「阶梯式假排版」，合并同类动作/念头 |
| `dash_overuse` | 全章 `——` ≥6 处且密度 ≥2.5/千字，或单段 ≥3 处 | 破折号泛滥导致文风断裂或翻译腔 |
| `punctuation_typography_hygiene` | 中文句内混入英文标点 `, . ? ! : ;`、装饰符号（`△★♥♛√`）或中文句中误插空格 | 番茄发稿前基础排版卫生硬伤 |
| `broken_line_wrap` / `broken_chapter_cut` | ≥2 段以逗号/顿号结尾强行换行；或章末最后一段未以完整句末标点收束 | 番茄「乱分行」「乱分章」或文本截断 |
| `rigid_connector_variants` | 旁白反复出现 ≥2 处 `不是……是……` / `是……是……`（`first_person` 下 `不是……而是` 亦 ≥2 处才报） | 句式过度工整显 AI 文风呆板 |
| `parallel_short_sentences` | 连续 ≥3 句/段非对白共享相同 ≥3 字起句前缀（面板/弹幕/规则条目豁免） | 机械同构短句排比 |
| `chronicle_filler_openers` | 单章 ≥3 段非对白以 `接着/然后/后来/随后/最后` 开头 | 流水账过渡词堆砌 |
| `structured_spec_list_dump` | 非 `rules` 模式下连续 ≥5 行短 `键：值` 罗列（系统面板/任务弹窗豁免） | 大段图纸/参数说明书式罗列，应拆进动作观察 |
| `opening_weather_cliche` / `ending_empty_preaching` | 章首前 2 段出现天气/晨起模板；或章尾 4 段旁白出现空泛哲理拔高 | 模板化开篇与无意义上帝视角升华 |
| `subjectless_run_on` / `pronoun_confusion_local` | >45 字 `望着/看着…让…` 或 >65 字无断句旁白；单段 ≤120 字内多人交锋高频连用 4–5 个“他/她” | 病句缺主语与局部代词指代混乱 |
| `character_name_typo_drift` | 传入 `--names` 或 `--char-card` 时，检出同姓一字之差低频误写（如 `林枫`→`林风`） | 番茄发稿前人名忽对忽错硬伤 |
| `mixed_quote_styles` / `zhihu_quote_style_mismatch` | 混用 `“”` 与 `「」`/`『』`；或 `--platform zhihu` 下仍使用 `“”` | 全篇引号体例不统一 |
| `bureaucratic_jargon_density` | 密集出现 ≥10 字正式公文书名号（以声明/协议/裁定/回执等结尾）或高频程序官话 | 滑向法务办件说明书腔，吸干情绪感染力 |
| `platform_chapter_length_limit` / `platform_title_length_limit` | 仅按需开启：单章 `non_ws_chars` 超平台区间或七猫标题 >18 字 | 上传前硬规格校准 |
| `ai_*` / `cliche_*` | 仅扫旁白（不扫角色台词）：纯翻译腔与工业废料（含 `cliche_knuckles_white` 骨节/指节发白） | 自动驾驶漏出的套话 |

## 4. 双轨签约编辑审稿门（A 轨工程体检 + B 轨感染力硬审）

`lint_webnovel.py` 0 警告只说明“壳子合格”，完稿或阶段交审须同步执行 **A + B 双轨审读**：

### A 轨：工程、排版与反向查错
1. 运行 `lint_webnovel.py`（建议加 `--char-card 00_脑洞与节拍.md`），排查分布跑偏与番茄投稿前排版硬伤；
2. 核对时间线、人名、称谓、金额、道具交接与 `01_轻量状态.md` 全程自洽；
3. **番茄反向通读查错法**：从尾段倒序向上快扫关键章，专捉“顺读脑补跳过去”的错别字、同音误字、`的/得/地` 误用与人名一字之差漂移；
4. 确认纯净导出零工程标记泄漏且章节序号连贯。

### B 轨：签约编辑感染力与活人感硬审（主观精读）
1. **痛感与情绪温度（按赛道适配）**：强情绪题材的核心背叛/转折处是否有真实刺痛与温度差？脑洞/规则题材是否立住紧迫悬念与爽感张力？
2. **微感官与描写减法**：全篇是否有 3–5 处贴合本篇场景的鲜活细节、二次动作或冷幽默，而非靠“指节发白、眼底熄灭、空洞地冷笑一声”走过场？细节能否过「情感/立体/反转」三问？
3. **人物活人感**：反派是否立住道德支点/沉没成本/局部正确性/真实盲区？配角是否拒绝工具化、拥有独立立场甚至拒绝配合过主角？
4. **双向节奏密度**：前 3 章是否章章有当场戏眼（无纯筹备水章），且关键交锋走了「受阻—尝试—再受阻—转折」拉锯（非一抬手秒杀）？章尾是否落在完整三节点？
5. **去公文腔复核**：高潮戏是否靠人际撕裂与台词潜台词炸出来，而非靠宣读公文与走程序？
6. **命名与标题复核（对照 [naming-and-titling.md](naming-and-titling.md)）**：角色名避开双套路拼装、龙套已降噪、目录章名竖扫不剧透且不连撞。

> B 轨任两项明显发虚，即使 A 轨 0 警告，也须定向精修提色。同时严守**镜子解读铁律**：`lint` 全为 `ADVISORY`，若有意为之的蓄势强段、毒舌吐槽或规则清单读感极爽，直接保留，绝不为了清零去硬切电报体或塞水对话。

## 5. 纯净导出（DOCX + TXT）与投稿清单

```text
python <skill-dir>/scripts/export_short.py \
  --chapters-dir <正文目录> \
  --out-docx <交付目录>/<书名>_全文.docx \
  --out-txt <交付目录>/<书名>_平台发布.txt \
  --title <书名> \
  --preset screen
```

- **单换行分段一致**：`export_short.py` 与 `lint_webnovel.py` 口径完全统一，每条非空正文行独立成段，保留 `* * *` 场景分割线，杜绝把手机短段粘成整块文字砖。
- **双端防泄漏与序号预警**：自动扫描**章标题 `# ...` 与正文全部段落**拦截残留工作台 ID（如 `RULE/CH/ARC/F/T/S-NNN`、`@CHAR-01`）及 `[待填：...]` / `{{...}}` 占位符；若 `# 第X章` 出现跳号或重号，会输出非阻断预警提示核对。
- **配套《投稿建书填表清单》**：当目标平台为 `qimao` / `fanqie` 或用户要求投稿信息时，读取 [platform-submission-tags.md](platform-submission-tags.md) 严格从平台预设原词库生成标准表单清单并存至 `交付/`（不混入 `正文/`）。
